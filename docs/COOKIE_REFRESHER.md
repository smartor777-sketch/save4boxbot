# Рефрешер куки YouTube (Playwright + постоянный профиль)

**Статус:** план реализации. Внедряется после апгрейда оперативки на prod.

## Зачем

YouTube ротирует сессии агрессивно: куки, экспортированные вручную, живут
~20–30 минут при автоматическом использовании (даже с одного IP), после чего
возрастные (18+) видео снова дают `Sign in to confirm your age`.

Решение — не экспортировать куки вручную, а держать на сервере **постоянный
браузерный профиль**, в котором один раз залогинены в YouTube. Скрипт каждые N
минут открывает youtube.com в этом профиле и переписывает свежие куки в
`cookies.txt`. Пайплайн yt-dlp при этом не меняется — он по-прежнему читает
`cookiefile`.

## Почему так (вместо альтернатив)

- **Нет повторных логинов по паролю** с облачного IP (это как раз палится и
  провоцирует ротацию). Профиль уже залогинен — YouTube сам держит сессию живой.
- **Пароль нигде не хранится** на сервере.
- **RAM не «течёт»:** браузер не держим запущенным. Схема
  *запуск → открыть → вытащить куки → закрыть* — процесс живёт секунды,
  профиль (логин) переживает закрытие на диске.
- Playwright (Python) — естественный выбор под наш Python-стек. Puppeteer
  требовал бы Node-сайдкара, Selenium тяжелее и капризнее в stealth-режиме.
- Рассмотренный репозиторий `devkulemannege/yt-dlp-Cookie-Sync` использует
  **логин по паролю каждый раз** (Flask + Xvfb) — не работает при CAPTCHA,
  требует аккаунт без 2FA, креды лежат открытым текстом. Не берём.

## Требования к железу

| Что | Значение |
|---|---|
| RAM: Chromium с 1 вкладкой YouTube | 400–700 МБ (до 300–400 МБ с `--disable-gpu`) |
| RAM: доступно на prod сейчас | ~2,4 ГБ (не хватает с запасом) |
| Решение | апгрейд RAM на prod, затем включение рефрешера |
| Своп | есть (4 ГБ) — страховка, но не основа |
| ЦП | 2 ядра — достаточно |

## Архитектура

```
┌─────────────┐   cron (каждые 30–60 мин)
│  скрипт     │───▶ launch_persistent_context(профиль)
│  refresh.py │      │  └─▶ goto youtube.com, ждём, берём ctx.cookies()
│             │      │  └─▶ закрываем браузер
│             │      ▼
│             │   merge: заменить youtube.com-строки в /opt/yt-bot/cookies.txt
└─────────────┘      │
                     ▼
              yt-dlp (читает cookiefile, как сейчас)
```

## Установка на prod

```bash
# 1. Python + Playwright
/opt/yt-bot/.venv/bin/pip install playwright
/opt/yt-bot/.venv/bin/playwright install chromium --with-deps

# 2. Папка профиля
mkdir -p /root/chromium-profile
```

## Первичный логин (один раз)

**Вариант A (рекомендуется) — логин на своём ПК, заливка профиля:**

1. Локально: `playwright install chromium`, затем запустить Chromium с
   `--user-data-dir=<папка>`, залогиниться в YouTube, закрыть.
2. Залить папку профиля на prod:
   ```bash
   pscp -r -pw ... "<папка_профиля>" root@31.76.8.29:/root/chromium-profile
   ```
   Пароль на сервер не попадает. Логин-сессия переносится вместе с профилем.

**Вариант B — логин прямо на сервере:**

1. `Xvfb :1 -screen 0 1280x800x24 & DISPLAY=:1` + x11vnc, подключиться VNC,
   открыть YouTube в Chromium с профилем, залогиниться, закрыть браузер.
2. `vncserver -kill :1`, Xvfb остановить.

После логина **проверить**, что профиль живой:
```bash
# под DISPLAY запустить браузер и открыть youtube.com — должна быть сессия
```

## Скрипт рефреша

`/root/cookie_refresher/refresh.py`:

```python
import asyncio
import os
import tempfile
from playwright.async_api import async_playwright

PROFILE = "/root/chromium-profile"
COOKIE_OUT = "/opt/yt-bot/cookies.txt"
YT_DOMAIN_MARK = "youtube.com"

def to_netscape(cookies) -> list[str]:
    lines = ["# Netscape HTTP Cookie File", "# generated by cookie refresher", ""]
    for c in cookies:
        domain = c.get("domain", "")
        if not domain or YT_DOMAIN_MARK not in domain:
            continue
        include_sub = "TRUE" if domain.startswith(".") else "FALSE"
        secure = "TRUE" if c.get("secure") else "FALSE"
        expires = int(c.get("expires") or 0)
        path = c.get("path") or "/"
        name = c.get("name", "")
        value = c.get("value", "")
        lines.append(f"{domain}\t{include_sub}\t{path}\t{secure}\t{expires}\t{name}\t{value}")
    return lines

async def refresh():
    async with async_playwright() as p:
        ctx = await p.chromium.launch_persistent_context(
            PROFILE,
            headless=True,
            args=["--disable-gpu", "--no-sandbox", "--disable-dev-shm-usage"],
        )
        page = await ctx.new_page()
        await page.goto("https://www.youtube.com", wait_until="domcontentloaded", timeout=60000)
        await page.wait_for_timeout(5000)
        cookies = await ctx.cookies()
        await ctx.close()
    return to_netscape(cookies)

def merge(cookies_txt: list[str]) -> None:
    with open(COOKIE_OUT, "r", encoding="utf-8") as f:
        existing = [ln for ln in f.read().splitlines()
                    if not (ln and not ln.startswith("#") and YT_DOMAIN_MARK in ln)]
    body = existing + cookies_txt + [""]
    fd, tmp = tempfile.mkstemp(dir=os.path.dirname(COOKIE_OUT))
    with os.fdopen(fd, "w", encoding="utf-8") as f:
        f.write("\n".join(body))
    os.chmod(tmp, 0o600)
    os.replace(tmp, COOKIE_OUT)

if __name__ == "__main__":
    lines = asyncio.run(refresh())
    if lines:
        merge(lines)
        print(f"OK: {len(lines) - 2} youtube-cookie lines written")
    else:
        print("FAIL: no youtube cookies — session lost?")
```

Замечания:
- **Атомарная запись:** пишем во временный файл + `os.replace` — yt-dlp никогда
  не увидит обрезанный файл.
- **Не перезаписываем чужие куки:** из `cookies.txt` убираются только
  `youtube.com`-строки, Instagram/TikTok остаются.
- Права `600`.

## Cron

```bash
cat > /etc/cron.d/cookie-refresh <<'EOF'
SHELL=/bin/bash
PATH=/usr/local/bin:/usr/bin:/bin
*/30 * * * * root /opt/yt-bot/.venv/bin/python /root/cookie_refresher/refresh.py >> /var/log/cookie-refresh.log 2>&1
EOF
```

Проверить: `grep youtube.com /opt/yt-bot/cookies.txt | wc -l` должен меняться
каждые 30 минут.

## Безопасность

- Профиль `/root/chromium-profile` — `chmod 700`, файл куки — `600`.
- Пароль на сервер не кладём (Вариант A логина).
- Куки — это живая сессия; `/opt/yt-bot/cookies.txt` уже в `.gitignore`.
- Если профиль «слетит» (Google сбросит сессию) — скрипт вернёт `FAIL`, в
  `cookies.txt` останутся старые куки, обычные видео продолжат работать.

## Откат

- Удалить cron `/etc/cron.d/cookie-refresh`, остановить ничего не нужно
  (браузер не держим запущенным).
- Вернуть `cookies.txt` из бэкапа при необходимости.
